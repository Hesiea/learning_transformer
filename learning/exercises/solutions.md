## P1 ｜ 两次前向的 loss 会相同吗

**要点（学员应覆盖到）**：

1. **训练模式下会不同** —— 因为 dropout 每次随机丢不同的神经元。
   本工程默认 `dropout=0.0`，所以教学配置下两次确实相同，但这是配置巧合，不是原理。
2. **`eval()` 模式下应当相同**：dropout 关闭，前向是确定性的。
   （前提是没有其它随机源，例如数据增强。）
3. **进阶要点**：即使数值相同，**反向传播在 cudnn 等后端上仍可能不确定**
   （原子加法的累加顺序），这是「可复现性」在工程上的真正难点。

**常见缺漏**：只说「dropout」而没提 `eval()`；不知道 dropout 在本工程是关闭的。

**判据**：能不能区分「确定性前向」与「可复现训练」这两个不同的概念。

## P2 ｜ 为什么掩码用 -inf 而不是 0

**要点**：

1. softmax 的输入是**未归一化的对数概率（logits）**，不是权重。
   softmax 之后才是权重，且 e⁰ = 1，**填 0 等于说「未来位置的相关性得分是 1」**，
   而不是「不要看它」。结果是被 mask 的位置照样分到概率。
2. 正确做法是填 `-inf`，因为 e^(−∞) = 0，softmax 后权重严格为 0。
3. **会在哪暴露**：
   - 训练时 loss 会异常地低（模型能偷看未来，等价于标签泄漏），
   - 而推理时（没有未来可看）质量断崖式下跌。
   这正是「因果性必须用数值验证」的原因 —— 03 讲里那个
   「只改最后一个 token、前面输出变化必须严格为 0」的测试就是干这个的。

**常见缺漏**：只说「要用 -inf」而说不出「0 代表得分为 1」这层含义。

## P3 ｜ 缩放里的 d_k 是几

**要点**：

1. `d_k = head_size = 16`，**不是** `n_embd = 64`。
   点积是在每个头自己的 `head_size` 维空间里做的，缩放要匹配这个空间的维度。
2. 为什么不能是 64：缩放的目的（03 讲实测过）是让点积方差回到 1 附近。
   点积的方差正比于参与点积的维度数，所以分母必须对应**实际做点积的维度**。
   用 64 相当于缩放过头（除以 8 而不是 4），softmax 会过于平坦，
   注意力分布趋近均匀 —— 不会报错，只是模型变弱。
3. **极端情形**：`n_head=1` 时两者恰好相等，所以这个 bug 只在多头时出现，
   这也是它容易被漏掉的原因。

**判据**：能不能把「缩放系数」和「实际点积维度」联系起来，而不是背公式。

## P4 ｜ train 降 val 升

**要点**：

1. 最可能是**过拟合**：模型开始记忆训练集而非学习规律。
2. 两种缓解手段（要说出机制）：
   - **增大 dropout**：前向时随机置零一部分激活，迫使模型不依赖特定神经元
   - **增大 weight decay**：把权重往 0 拉，限制模型容量
   - 其它可接受：**增加数据**、**减小模型**、**早停**
3. **关键追问（多数人会漏）**：这**未必**是过拟合。还可能：
   - **验证集与训练集分布不同**（例如语料切分时把同一部作品切到了两边，
     或中英文混语料的前后段风格不一致）
   - **纯噪声**：本工程对 val 用 20 个 batch 取平均，但如果只评估了 1~2 个 batch，
     这种量级的波动可能只是采样噪声

**判据**：能否主动怀疑「前提」而不是顺着题面接受「这是过拟合」。
这一条是 C2（识别混淆变量）的直接体现。

## P5 ｜ block_size 放大后缓存收益怎么变

**要点**：

1. 无 cache 的累计计算量 ∝ T²（准确说是每步重算整段历史，总计约 T²/2 次 token 前向），
   有 cache 时 ∝ T。所以**比值 ∝ T**，T 从 64 到 1024 大约翻 16 倍。
2. 平衡点由**固定开销**与**省下的计算**两者决定。固定开销包括：
   `torch.cat` 拼接、掩码构造、每步的 Python/调度开销。
   模型越大（n_layer、n_embd 越大），单次前向越贵，省下的部分越占优，
   平衡点就越靠左（更短的长度就开始有收益）。
3. 因此：**模型越大、序列越长，KV Cache 收益越明显**；
   小模型短序列下几乎无收益（实测 1.05x 就是这个原因）。

**常见缺漏**：只说「会更快」而说不出比值 ∝ T；忽略固定开销的存在。

## P6 ｜ 陷阱题：头数实验的混淆变量

**要点**：

1. **混淆变量是 `head_size`**：固定 `n_embd=128` 时，
   `n_head=1 → head_size=128`，`n_head=8 → head_size=16`。
   你改的是两个量，不是一个。所以「1 头最好」可能只是「head_size 大更好」。
2. **正确设计**：固定 `head_size`，让 `n_embd = n_head × head_size` 一起变
   （例如 head_size 固定 64：n_head=1→n_embd=64，n_head=2→128，n_head=4→256）。
   但这样参数量又变了 —— 所以还要在结论里说明
   **「同等参数量下」与「同等 head_size 下」是两个不同的问题**，选一个作为口径并写明。
3. **额外要点**：小步数下的排序本身不可靠，必须多种子重复
   （这正是 `src/experiments/` 里 `--seeds` 参数的用途）。
4. 如果学员指出「应该先跑够步数再比较」，额外加分。

**判据**：这是 C2 与 C3 的综合考点 —— 能不能在别人给的结论里看出设计缺陷。

## P7 ｜ 跨语言比较该用什么指标

**要点**：

1. 交叉熵是**每 token 的平均负对数似然**，单位是 nat，
   它依赖词表大小：随机基准是 `ln(V)`，所以 V 不同就不能直接比。
2. 推荐指标一：**每字符比特数（bits per character, BPC）**
   换算：`BPC = loss_nat / ln(2) / (每 token 对应的字符数)`。
   字符级 tokenizer 下「每 token 字符数 = 1」，所以 `BPC = loss / ln(2) ≈ loss / 0.6931`。
   这个指标与语言无关，可以跨语种比较。
3. 推荐指标二：**压缩率**（原始文本字节数 / 模型对文本的编码长度），
   本质与 BPC 等价，工程上更直观。
4. 可以提一句：这也是为什么论文里常报 BPC 而不是 loss。

**常见缺漏**：只说「用困惑度」——困惑度 `exp(loss)` 同样依赖 V，**不能**跨词表比较。
这是非常常见的误解，如果学员犯了这个错，一定要记进 `mistakes.md`。

## 批改方式（给 Agent 的操作规范）

1. 先让学员念他自己的答案，**不要打断**
2. 只指出**缺失的环节**，用提问引导：「如果 softmax 的输入不是概率，那 0 意味着什么？」
3. 学员补上后再对照要点确认，不要越俎代庖
4. 答错的条目写进 `../mistakes.md`，并按 1 天 / 7 天 / 30 天排重考
5. 全对也要问一句「有没有例外情况？」—— 大多数题都有边界条件
