# 用 AGENT 做长期学习：把「问答」改造成「共同研究」

> 这份文档回答一个问题：**在这个 transformer 工程里，接下来几个月怎么持续学下去**，
> 以及怎么让 AI 助手真正参与进来，而不是变成一个更快的搜索引擎。

---

## 一、先承认一件事：为什么大多数人用 Agent 学习最后都退化成问答

对照着看，你自己的使用模式属于哪一种：

| 典型用法 | 你实际获得了什么 | 长期后果 |
|---|---|---|
| 「这块代码什么意思？」 | 一段解释 | 读的时候懂，合上就忘 |
| 「帮我写一个多头注意力」 | 一份能跑的代码 | 代码是你的，理解不是 |
| 「为什么 loss 不下降？」 | 一堆可能原因 | 试到了某个能跑通就停了，不知道为什么 |

问题不在答案质量，而在**三个结构性缺陷**：

1. **没有跨会话记忆**。Agent 每次醒来都是白纸，于是你每次都要重述背景——
   最后你干脆只问不需要背景的碎片问题。
2. **被动等待被问**。你不问，它不动。于是学习节奏永远由「你此刻想到什么」决定，
   而不是由「知识地图上缺哪一块」决定。
3. **最危险的一点：它会替你思考，而你不自知**。解释读起来总是通顺的，
   通顺会被大脑误判成理解。**真正的理解只能由「预测 → 验证 → 修正」产生**，
   而这三步恰好是问答模式完全绕过去的。

所以方案的核心不是「更好的提问技巧」，而是**换一种协作结构**。

---

## 二、Agent 在学习中真正不可替代的五件事

想清楚它擅长什么，才知道该把什么交给它。以下五件事，人单独做都很痛苦：

| 能力 | 具体是什么 | 为什么人类做不到 |
|---|---|---|
| **批量实验** | 一个变量扫 8 个取值、3 个种子、跑完列表格 | 手工改 24 次配置会疯 |
| **代码考古** | 「`wpe` 这个权重在哪几处被读写？都受什么影响？」 | 跨 5000 行追踪引用很累 |
| **代价为零的多角度解释** | 同一个概念要 5 种讲法（类比/数学/代码/几何/反例） | 你只能找到一位老师 |
| **对抗性审查** | 指出「你这次的实验混淆了两个变量」 | 人容易自我确认 |
| **无疲劳的陪练** | 出题、收答案、批改、记录错题、隔期重考 | 没人愿意当你的判分器 |

**反过来，Agent 不该替你做的三件事**：
写下你自己还没想通的代码、给出你还没尝试过的答案、替你判断「我懂了」。

## 三、核心机制：把项目文件变成 Agent 的长期记忆

Agent 没有记忆，但**仓库有**。所以让仓库承担记忆——这是整个方案的地基。

建议建立这个结构（当前工程还没有任何学习记录类文件）：

```
learning/                          ← 新建：你的学习档案，随代码一起提交
├─ progress.md                     进度表：每讲的掌握状态 + 验收证据
├─ log.md                          学习日志：每次会话结束写【我的】结论
├─ mistakes.md                     错题本：错误理解 → 正确理解 → 重考日期
├─ questions.md                    悬而未决的问题（开放问题队列）
├─ experiments/                    实验记录，一次实验一个文件
│   ├─ 0001_head数到底有没有用.md
│   └─ 0002_中文与英文词表大小对比.md
└─ exercises/                      主动回忆题库（答案单独放，防止偷看）
    ├─ problems.md
    └─ solutions.md
```

### 关键设计：`progress.md` 用「证据」而不是「已学」来标记状态

「已学完 03 讲」是自我感觉，「能复述 Q/K/V 分工并解释 1/√d_k」是可验证的。
建议每个知识点用四档标记，并且**升档必须有证据**：

| 状态 | 含义 | 升档需要的证据 |
|---|---|---|
| ⬜ 未开始 | — | — |
| 🟡 读过 | 看过讲解 | 无 |
| 🟠 能复述 | 合上代码能讲清原理 | 在 `log.md` 里用自己的话写一段 |
| 🟢 能预测 | 改一个变量能预判结果并实测验证 | 一条 `experiments/` 记录 |
| 🔵 能迁移 | 能在新场景用出来（换语料/换结构/写新变体） | 一个自己发起的小项目 |

这份表就是 Agent 的「读心术」：它一开始读这张表，就知道你在哪、该推你往哪走。

### 会话协议（写进 `AGENTS.md`，Agent 每轮自动遵守）

**开场（你说「继续」时 Agent 必须做）**：
1. 读 `progress.md` 与最近一篇实验记录，用三五句话复述「我们上次停在哪」
2. **不要立即解释概念**，先提出一个可验证的小问题或小实验
3. 给出本轮的具体产出物（改哪个文件、跑哪条命令、看哪个数字）

**收尾（Agent 必须做）**：
1. 把本轮结论写进 `log.md`，但**必须区分「学员的结论」与「Agent 的补充」**
2. 更新 `progress.md` 状态，并注明证据出处
3. 留 1~3 个开放问题进 `questions.md`
4. 如果发现理解偏差，写进 `mistakes.md` 并排一个重考日期

**禁止（写进 `AGENTS.md` 的红线）**：
- 不直接给答案，先要求你预测，再验证
- 不写你还没想通的代码；要写就写「最小可验证片段」并标注哪几行是核心
- 不宣称做过未验证的事；所有结论必须附命令与实际输出
- 不静默改你的实验记录，改动要标出来

## 四、单次实验的标准流程（这是长期学习的最小循环单元）

每学一个点，都跑一遍这个六步循环，产出物是一个 `experiments/xxxx_标题.md`：

1. **提问**：这个实验要回答什么？（一次只问一个问题）
2. **预测**：*先写下你认为结果会是什么，以及为什么* ← 最容易跳过、也最重要的一步
3. **设计**：改哪个变量、控制哪些变量、看什么指标（工程里已有 `--steps/--seeds` 支持）
4. **执行**：Agent 跑，把命令和原始输出贴进记录
5. **对账**：实际结果 vs 你的预测 —— **不一致的地方才是真正学到东西的地方**
6. **结论 + 新问题**：一句话结论，以及它引出的下一个问题

> 第 2 步是全部价值所在。没有预测的实验只是「跑了一下代码」，
> 有了预测，实验才变成「对你的心智模型做了一次检验」。

工程现状对这套流程很友好：`common/gpt.py` 的组件都可替换、训练脚本支持
`set_seed` / `--steps` / `--seeds`、`src/experiments/` 已有两个可复用的消融脚手架。

## 六、主动回忆与间隔重复：解决「读完就忘」

长期学习最大的敌人不是难度，是遗忘。建议用 `learning/exercises/` 做轻量版间隔重复：

- **出题**：让 Agent 从已完成的讲次出题，要求「不给代码、只给场景」
  （例：如果去掉 `1/√d_k`，训练早期会发生什么？怎么用实验证伪你的判断？）
- **作答**：你先在 `problems.md` 里写，写不出来就是没学会——这是有效信号
- **批改**：Agent 对照 `solutions.md` 指出缺漏，不直接给标准答案
- **重考**：错题进 `mistakes.md`，约定 1 天后、7 天后、30 天后各重考一次

这套机制不需要任何软件，就是几个 Markdown 文件加 Agent 的配合。

## 七、分工原则（谁负责什么）

| 学习环节 | 你 | Agent |
|---|---|---|
| 阅读与理解 | **主责** | 提供多角度解释、反例、易混淆点辨析 |
| 提出预测 | **主责** | 追问「为什么这么预测」，不接受「我猜」 |
| 设计实验 | 参与 | 主责（控制变量、估规模、选指标） |
| 跑实验 | 偶尔 | **主责**（批量、复现、整理输出） |
| 得出与记录结论 | **主责** | 校对、指出过度推广 |
| 出题与批改 | 作答 | **主责** |
| 维护档案 | 审阅 | **主责** |

一条底线：**结论必须由你写下来**。Agent 代写的结论不算你的理解。

## 八、关于工具与权限的现实约束（重要）

这个工程当前的运行环境有两个必须知道的事实，它们会直接影响长期学习的体验：

1. **shell 访问工作区需要授权**。当前沙箱策略是 `workspace-write`，
   实测 `powershell` 直接被拒绝访问 `F:\26362\AI\transformer`。
   这意味着：**每个需要跑代码、跑训练、执行 git 的会话，你都要批准一次权限**。
   建议做法：会话开头明确说「本轮要跑实验，请开 full access」，
   而不是让 Agent 反复撞墙重试。

2. **网络需要代理**。本机只有 `127.0.0.1:10809` 在监听（git 全局配置已改到此端口，
   原先是 7890）。代理不开时，下载语料、安装依赖、`git push` 都会失败。

另外，`.venv`(591MB)、`tools`(78MB)、`data`、`out` 都不在 git 里，
所以**换机器或重装后需要重跑**：`scripts\setup_env.ps1` → `scripts\download_data.ps1`
→ `scripts\prepare_data.py`。学习档案 `learning/` 反而应该提交，那是你的资产。

## 九、怎么判断这套方案起作用了

三个月后回看，如果出现下面这些信号，说明方向对了：

- ✅ `progress.md` 里 🟢🔵 的比例在上升，而不是 🟡 堆积
- ✅ `mistakes.md` 里出现过「我原以为 X，实际是 Y」的具体记录
- ✅ 你能提出 Agent 没提示过的问题（这是从「被动接收」转向「主动研究」的分水岭）
- ✅ 你有过至少一次「预测错误 → 修正心智模型」的经历，并能说清改了什么
- ❌ 反面信号：`log.md` 全是 Agent 的口吻；实验记录里没有「预测」那一节
